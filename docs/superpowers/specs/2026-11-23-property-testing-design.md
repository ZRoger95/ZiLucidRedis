# 核心纯函数属性测试设计

日期：2026-11-23
状态：已实现
范围：为 `src/lib/` 的 secrets、persistence、parseConf、exportConf、normalizeConf 建立基于属性的测试，并固化「纠正 → 确定性检查」流程规则。不覆盖运行时 UI 验证。

## 意图：为什么做

明文密码不落盘是本项目唯一的单向门风险：一旦泄漏进导出文件或 `localStorage` 就不可逆。当前守护它的只有例子测试（`tests/secrets.test.ts` 7 例、`tests/persistence.test.ts` 4 例），覆盖的是「想到的输入」；而敏感行的输入空间（空白 × 引号 × 多密码 × 注释 × 换行符的组合）近乎无限，安全不变量必须对所有输入成立。

现状还有一个结构性特点：替换逻辑（`secrets.ts` 的 `replaceSecrets`）与持久化守卫（`persistence.ts` 的两条正则）是**两套独立实现**，二者的一致性由 `tests/persistence.property.test.ts` 的跨模块性质固定。设计时存在的三个接缝已修复，并由回归例子与性质测试固定现状：

- CRLF 行尾的敏感行曾被 `shapeLine` 整体跳过（`.` 不匹配 `\r`），明文原样保留；现 `shapeLine` 容忍行尾 `\r`，CRLF 与 LF 行为一致。
- 字面 `${env_*}` 占位符与真实密码混排时还原计数曾错位；现占位符目标同样登记进 vault（值为其自身），`user` 行无 `>` 前缀的占位符 token 也进入目标序列，按位置排序对齐。
- 守卫曾把引号包裹的占位符误判为明文而拒绝持久化；现两条正则的负向前瞻容忍单双引号。

`replaceSecrets` 重建敏感行时把指令名与值之间的空白归一为单个空格，这是现状行为：字节级往返只对规范形态输入断言，任意形态以 `parseConf` 后的语义等价断言。

占位符目标按其自带 env 名登记、vault 存内层占位符：引号包裹的占位符往返不被加套引号，占位符 env 名与指令名不一致时还原也不出错位。`user` 行的内层占位符匹配若已落在 `>token` 范围内则跳过，避免同一占位符重复登记。

## 目标与边界

目标：

- 引入 fast-check 作为 devDependency，在 Vitest 内运行性质测试；运行时依赖零新增。
- 生成器两路：结构化生成敏感行（覆盖 `requirepass`、`masterauth`、`tls-key-file-pass`、`tls-client-key-file-pass` 与 `user` 行多密码，**植入已知明文**）；对 `src/data/official/*.conf` 做变异（增删行、截断、字符替换）。
- 四组不变量成为可执行事实：
  1. **无明文泄漏**：`replaceSecrets` 输出不含任何植入明文，也不含 vault 中任何值；`found > 0` 时输出必含占位符。
  2. **还原正确性（两级）**：规范形态输入（单空格分隔、LF、末尾换行）满足字节级往返；任意形态输入满足语义级往返（`parseConf` 后指令与参数等价）。
  3. **跨模块一致性**：对任意文本，`replaceSecrets` 的输出交给 `saveState` 不得抛错；持久化产物不含植入明文；`exportWithSecrets` 能语义还原。
  4. **解析健壮性与归一化幂等**：`parseConf` 对任意字符串与变异输入不抛异常；`normalizeConfig` 幂等且第二遍 `droppedComments` 为 0；`exportOriginal` 幂等。
- 每个接缝必须有结论：确认缺陷则最小修复并留回归测试；确认非缺陷则用不变量把现状固定下来。不允许静默跳过。
- 流程规则落地：能表达成 Lint/类型约束的纠正优先做成确定性检查而非文档；反复被误用的 API 改签名让误用编译不过。写入 `AGENTS.md` 与 `docs/engineering/eslint.md`。

非目标：

- 运行时 UI 验证（功能地图 + 浏览器冒烟）另行设计，不在本 spec 内。
- 不引入形式化方法、自动合并、外环自动化。外环触发条件：CI 内环长期稳定绿之后；其中只报告型定时模糊（nightly 更多轮/新 seed、只报告不合并）可先行，自动合并需误报率与回滚率的长期证据。整体优先级见 [运行时验证 spec](2026-11-24-runtime-verification-design.md) 的「缓行项优先级」。
- 不改变 `replaceSecrets` 的空白归一化行为；用两级不变量固定该现状，如需改变另行设计。
- 不为 `handoff.ts` 建性质测试：vault 只存模块级内存变量，无序列化面。
- 不改 CI 与部署配置；README 的 `npm test` 描述不受影响，无需改动。

## 方案

已选：**fast-check + Vitest，植入式生成器，两级不变量**。生成器在构造输入时记录植入的明文集合，性质断言针对「植入的全部明文」而非仅 vault 内容——这样同时验证「替换的完整性」（该抓的都抓了）和「替换的正确性」（抓到的不泄漏）。失败反例依赖 fast-check 的收缩与 seed 重放，最小反例固化为回归测试。每条性质默认 100 次运行，关键安全性质 500 次，全部性质测试的时间增量控制在秒级。

放弃的方案：

- **手写随机生成 + 循环断言**：没有反例收缩和 seed 重放，失败后定位与复现成本高，等于自造一个劣质 fast-check。
- **继续枚举例子测试**：组合空间追不上，两套实现的一致性仍靠运气；例子测试保留，但不再作为安全不变量的主要防线。
- **独立模糊测试脚本（Vitest 之外）**：失败不进入 `npm run check` 回归闭环，与现有门禁脱节，违背「纠正 → 确定性检查」的初衷。
- **顺手修改 `replaceSecrets` 保留原始空白**：超出本设计范围的行为变更；先用不变量固定现状，确有需要再单独设计。

## 验收标准

- 四组不变量均有性质测试且 `npm run check` 通过；`npm run build` 通过。
- 三个接缝各有复现测试与明确结论（修复 + 回归，或确认为现状并被不变量固定）。
- 生成器覆盖四类敏感指令、`user` 多密码、引号/空白/CRLF/注释变体；官方 conf 变异输入进入解析性质。
- 性质测试可 seed 重放，总时长增量在秒级；运行时依赖零新增。
- `AGENTS.md` 与 `docs/engineering/eslint.md` 含「纠正 → 确定性检查」流程规则。
