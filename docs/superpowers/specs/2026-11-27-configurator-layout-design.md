# 配置向导页面布局调整设计

日期：2026-11-27
状态：已实现
范围：只调整 `/configurator` 的页面级布局，不改步骤内容、控件行为、草稿、生成逻辑或体检页。整体向导设计见 [2026-11-19-configurator-design.md](2026-11-19-configurator-design.md)，步骤内部布局见 [2026-11-20-configurator-step-skeleton-design.md](2026-11-20-configurator-step-skeleton-design.md)。

## 1. 意图

移除右栏后，窄内容步骤在左侧贴着导航，右侧留下大片空白；顶部标题与版本号的视觉基线不一致；底部操作区仍沿用旧左右顺序。本次只校正页面骨架，让内容更均衡、顶部信息更整齐、底部操作更符合使用顺序。

## 2. 目标

- 当前步骤在内容区内按自身最大宽度居中，左右留白均衡。
- 顶部「生成配置」与「当前版本 8.8」共享视觉基线。
- 底部左侧显示「已改 N 项」，右侧放置「上一步 / 下一步」按钮组。
- 保持 1024px 最小宽度下无横向溢出，区域步的双列与说明栏断点行为不变。

## 3. 非目标 / 反目标

- 不改侧栏宽度、步骤顺序、字段布局、说明内容、颜色或控件样式。
- 不把窄页拉满，也不为桌面端增加移动端适配。
- 不通过全局 CSS 或魔法数值覆盖各步骤现有最大宽度。

## 4. 方案

已选：**方案 B —— 按内容宽度居中**。内容区保留现有 `px-8 py-6`，各步骤根容器补 `mx-auto w-full`，继续使用现有 `max-w-3xl` / `max-w-6xl`。这样版本页、问卷页保持阅读宽度，字段密集页在宽屏居中，在 1024px 下自然收缩到可用宽度。

放弃的方案：

- **方案 A —— 左对齐并加大内边距**：实现最小，但右侧空白仍然明显，只是把起点向右推。
- **方案 C —— 拉满可用宽度**：能消除空白，但版本线、说明和操作项会被过度拉伸，削弱现有阅读节奏。

顶部把标题与版本号收进同一组，用 `items-baseline` 对齐，并统一 `leading-5`；右侧返回体检与仓库链接保持垂直居中。底部调整为「已改项 → 弹性留白 → 按钮组」。

## 5. 约束与验收

- 仅使用现有 Tailwind 布局类，不新增组件、依赖或样式文件。
- 1440px 与 1024px 下，当前步骤左右留白均衡且无横向滚动。
- 顶部标题与版本号基线一致；底部已改项在左、按钮组在右。
- `npm run check` 与 `npm run build` 通过，并在浏览器中复核版本页与字段密集区域页。
