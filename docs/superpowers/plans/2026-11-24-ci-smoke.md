# CI 冒烟集成实施计划

状态：已实现（`!!process.env.CI` 被 ESLint no-implicit-coercion 要求替换为 `Boolean(process.env.CI)`；upload-artifact 补充 `include-hidden-files: true`，否则隐藏目录 `.screenshots` 下的产物被默认排除；PR #1 首跑绿，已 squash 合并）

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把 `npm run smoke` 接入 GitHub Actions：新增 ci.yml 在 push master / PR 时跑完整验证，deploy.yml 插入冒烟门禁，坏版本发不出去。

**Architecture:** 两条 workflow 跑同一套 `npm run smoke`。ci.yml 只测试不部署；deploy.yml 触发时机与部署职责不变，仅在 build 与上传 Pages 产物之间插入冒烟。`playwright.config.ts` 以 `process.env.CI` 区分环境：CI 下 webServer 只 preview（dist 已由 build job 产出）、禁止复用 server、github reporter、forbidOnly。失败上传截图与 trace artifact。

**Tech Stack:** GitHub Actions（ubuntu-latest、Node 24）、@playwright/test、chromium（官方 CDN）。

**Spec:** `docs/superpowers/specs/2026-11-24-ci-smoke-design.md`

## Global Constraints

- 不改冒烟用例断言、产品代码与文案；`e2e/` 仍不进 `npm run check`。
- 本地 `npm run smoke` 行为与产物路径不变。
- retries 保持 0；不做浏览器缓存、矩阵与分片。
- 不新增运行时依赖；不改 `npm run check` 组成。
- 不代用户创建提交或推送；PR 上的 CI 首跑验证由用户推送后完成。
- 完成前运行 `npm run check`、`npm run build` 与 `npm run smoke`。

## Review Focus

- deploy.yml 中冒烟必须在 `npm run build` 之后（CI 下 webServer 只 preview，依赖已有 dist），且在上传 Pages 产物之前。
- `reuseExistingServer` CI 下必须为 false，避免陈旧 server 假绿。
- upload-artifact 用 `if: failure()`，路径含 `.screenshots/smoke/` 与 `.screenshots/smoke-results/`（trace）。
- ci.yml 的 push 与 pull_request 都限定 `master`，避免 PR 分支 push 双重触发。
- `playwright.config.ts` 改动须过 ESLint（strict、无注释）与 Prettier。
