# 左右栏内置查找实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 左栏编辑器与右栏官方 conf 各自支持 `Ctrl+F` / `⌘F` 打开 VS Code 风格查找条，带大小写、全词、正则三种开关。

**Architecture:** 新增纯函数匹配引擎 `src/lib/find.ts`，两栏共用一个无 effect 的展示组件 `FindWidget`。`Editor` 用 CodeMirror 的 mark 装饰高亮，`OfficialPane` 用行级 `<mark>` 与 `memo` 化行组件；`App` 只记录最近激活栏并把 `mod+f` 路由成对应栏的请求计数。

**Tech Stack:** React 19、TypeScript strict、CodeMirror 6、Tailwind 4、shadcn/ui、Vitest + Testing Library（jsdom）。

**Spec:** `docs/superpowers/specs/2026-11-18-pane-find-design.md`

## Global Constraints

- 纯前端，运行时零外部请求；不新增后端与运行时网络依赖。
- `src/lib/` 必须是纯函数，不允许依赖 React / react-dom。
- TypeScript strict，不新增 `any`；共享类型优先放 `src/types.ts`，查找专属类型放 `src/lib/find.ts`。
- 禁止直接使用 `useEffect` / `useLayoutEffect`；只有 `src/App.tsx`、`src/components/Editor.tsx`、`src/components/OfficialPane.tsx`、`src/hooks/useShortcut.ts` 在允许清单内。`FindWidget.tsx` 不得使用 effect。
- shadcn 控件只从 `@/components/ui/<name>` 子路径导入；样式用 Tailwind；CodeMirror 生成 DOM 的样式写 `src/components/editor.css`。
- UI 文案中文；桌面端最小宽度 1024px。
- 每个任务先写能复现的测试，再改实现；`npm run check` 零告警。
- 正则使用 JavaScript 语法，不承诺 PCRE。
- 「只看差异」下只搜当前可见行。

## Review Focus

- macOS `⌘F` 与 Windows/Linux `Ctrl+F` 都必须打开查找条，浏览器自带查找不得出现。
- 中文输入法组合输入（`isComposing`）时按 `Enter` 不得跳转命中。
- 右栏两千多行时，每次按键不能整列重渲染；未命中行保持稳定。
- 正则 + 全词 + 大小写组合、非法正则、零宽正则都不能崩溃或死循环。
- 「只看差异」隐藏的行不得被计数或跳转。

import { expect, test } from 'vitest';

import { DEFAULT_FIND_OPTIONS, findMatches } from '../src/lib/find';

test('空查询没有命中', () => {
  expect(findMatches('maxmemory 0', '', DEFAULT_FIND_OPTIONS)).toEqual({ matches: [], error: false });
});

test('默认大小写不敏感，并返回行号', () => {
  const text = 'MaxMemory 0\nmaxmemory 1';
  const { matches } = findMatches(text, 'maxmemory', DEFAULT_FIND_OPTIONS);
  expect(matches.map((match) => match.lineNo)).toEqual([1, 2]);
  expect(text.slice(matches[1].from, matches[1].to)).toBe('maxmemory');
});

test('区分大小写时只命中完全一致的大小写', () => {
  const { matches } = findMatches('MaxMemory 0\nmaxmemory 1', 'maxmemory', {
    ...DEFAULT_FIND_OPTIONS,
    caseSensitive: true,
  });
  expect(matches).toHaveLength(1);
  expect(matches[0].lineNo).toBe(2);
});

test('非正则模式下特殊字符按字面匹配', () => {
  const { matches } = findMatches('maxmemory-policy allkeys-lru', 'maxmemory-policy', DEFAULT_FIND_OPTIONS);
  expect(matches).toHaveLength(1);
});

test('全词匹配排除前缀更长的单词', () => {
  const { matches } = findMatches('maxmemory maxmemoryx', 'maxmemory', {
    ...DEFAULT_FIND_OPTIONS,
    wholeWord: true,
  });
  expect(matches).toHaveLength(1);
  expect(matches[0].from).toBe(0);
});

test('正则模式支持 JavaScript 正则', () => {
  const { matches } = findMatches('maxmemory 256mb\nmaxclients 10000', 'max\\w+', {
    ...DEFAULT_FIND_OPTIONS,
    regexp: true,
  });
  expect(matches).toHaveLength(2);
});

test('正则与全词同时开启时仍按词边界过滤', () => {
  const { matches } = findMatches('xmaxmemory maxmemory', 'max\\w+', {
    ...DEFAULT_FIND_OPTIONS,
    regexp: true,
    wholeWord: true,
  });
  expect(matches).toHaveLength(1);
  expect(matches[0].from).toBe(11);
});

test('非法正则返回 error 且没有命中', () => {
  expect(findMatches('maxmemory', '[', { ...DEFAULT_FIND_OPTIONS, regexp: true })).toEqual({
    matches: [],
    error: true,
  });
});

test('零宽正则不会死循环', () => {
  const { matches } = findMatches('a\nb', '^', { ...DEFAULT_FIND_OPTIONS, regexp: true });
  expect(matches).toHaveLength(2);
  expect(matches.map((match) => match.lineNo)).toEqual([1, 2]);
});

test('skipLines 中列出的行不计入命中', () => {
  const { matches } = findMatches('x 1\nx 2\nx 3', 'x', DEFAULT_FIND_OPTIONS, new Set([2]));

- [ ] **Step 3: 实现 `src/lib/find.ts`**

实现要点：

- 非正则模式用 `query.replaceAll(/[.*+?^${}()|[\]\\]/g, '\\$&')` 转义。
- 标志位：`options.caseSensitive ? 'g' : 'gi'`；`new RegExp` 放在 `try/catch` 中，失败返回 `{ matches: [], error: true }`。
- 计算行号：先建 `lineStarts`（`[0]`，每遇到 `'\n'` push `index + 1`），命中按顺序前进一个行指针，避免每命中都切字符串。
- 全词过滤：命中前一个字符（`text[from - 1]`）或后一个字符（`text[to]`）属于 `\w`（`/^[A-Za-z0-9_]$/`）时丢弃；正则模式下同样过滤。
- 零宽命中：`match[0].length === 0` 时手动 `regex.lastIndex += 1`，避免死循环。
- `skipLines` 在算出 `lineNo` 后过滤。
- 结果按 `from` 升序，`matches` 为空时返回同一空数组常量即可。

- [ ] **Step 3: 实现 Editor 查找状态与装饰**

- 从 `../lib/find` 导入 `DEFAULT_FIND_OPTIONS`、`findMatches`、类型 `FindMatch`、`FindOptions`；从 `./FindWidget` 导入组件。
- 状态：`findOpen`、`findQuery`、`findOptions`、`findIndex`；`findInput` 为 `useRef<HTMLInputElement>(null)`；`lastFindRequest` 记录已处理的 `findRequest`。
- 抽局部函数 `isQuietLine(result, lineNo, forceVisibleLines)`，把 `buildDecorations` 里现有的 `quiet` 判断改为调用它。
- `hiddenLines`：仅在 `props.onlyDiff` 时构建 `Set<number>`，逐条 `result.lines` 用 `isQuietLine` 判断。
- `findResult = useMemo(() => findMatches(props.value, findQuery, findOptions), [props.value, findQuery, findOptions])`；`matches` 在 `hiddenLines` 存在时过滤掉隐藏行；`findOpen` 为 false 时用模块级空数组常量。
- `activeIndex`：`matches.length === 0 ? -1 : ((findIndex % matches.length) + matches.length) % matches.length`；`activeMatch = matches[activeIndex]`。
- 处理函数：`onQueryChange` 与 `onOptionsChange` 同时把 `findIndex` 归零；`onNext` 在 `matches.length > 0` 时 `setFindIndex(findIndex + 1)`；`onPrev` 同理减一；`onClose` 设 `findOpen=false` 并 `view.current?.focus()`。
- effect 1：`props.findRequest` 变化（与 `lastFindRequest` 不同）时 `setFindOpen(true)`，并更新 ref；首次挂载不因历史值打开。
- effect 2：`findOpen` 变为 true 或 `props.findRequest` 变化时，`findInput.current?.focus()` 与 `.select()`。
- 搜索装饰：新增 `searchCompartment = useRef(new Compartment())`；新增 `buildFindDecorations(state, matches, activeIndex)` 返回 `Decoration.set`，逐条命中用 `Decoration.mark({ class: index === activeIndex ? 'cm-find-match cm-find-current' : 'cm-find-match' })`（当前命中同时带两个类，便于选择器断言与样式覆盖）；用 effect 在 `matches` / `activeIndex` 变化时 `reconfigure`。
- 跳转 effect：`findOpen && activeMatch` 时 dispatch `selection: { anchor, head }`（注意 clamp 到文档长度）与 `EditorView.scrollIntoView(activeMatch.from, { y: 'center' })`；不要调用 `instance.focus()`。
- 渲染：把原 `<div className="editor-host" ref={host} />` 包进 `<div className="relative flex min-h-0 flex-1 flex-col">`，先渲染 `<FindWidget>`（`label="在你的配置中查找"`、`inputRef={findInput}`、`activeIndex`、`matchCount={matches.length}`、`invalid={findResult.error}`），再渲染 host。
- `editor.css` 追加 `.cm-find-match { background: #fde68a; }` 与 `.cm-find-current { background: #f59e0b; }`。
